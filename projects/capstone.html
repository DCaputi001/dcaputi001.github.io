Capstone Project

Financial-Planner | Secure Software Enhancement

Project Overview

This capstone project represents the culmination of my Computer Science degree at SNHU. The project focuses on analyzing, reviewing, and enhancing an existing financial services API for Artemis Financial, with specific emphasis on secure coding practices, code quality, and industry standards.

Code Review

Before beginning enhancements, I performed a full code review using a combination of:

  • CS-499 Code Review Checklist
  • OWASP secure coding guidelines
  • SmartBear’s peer review best practices
  • Meta engineering research on review efficiency

The goal of the review was to identify vulnerabilities, inefficiencies, and areas for improvement in algorithmic performance, software design, and overall code reliability.

Software Engineering Enhancement

For the Software Engineering outcome, I refactored the original investment calculation artifact to improve maintainability, readability, security, and alignment with modern software development best practices. The original version of the code contained several issues, including duplicated logic, magic numbers, inconsistent naming conventions, lack of modularity, and minimal error handling. These issues made the calculation process difficult to maintain and posed potential security risks.

The refactored version applies clean coding principles, modular design, and secure engineering practices. Redundant logic was moved into helper methods, all constants were extracted into symbolic values, and structured validation was added to ensure that all incoming parameters remain within acceptable ranges. Input handling and error messages were also improved to prevent unintended crashes and to better guide the user when incorrect data is provided.

Additionally, the controller now follows a more RESTful structure, clearly separating business logic from routing concerns. This improves the separation of concerns, testability, and future scalability of the application. The improved version also aligns with secure coding principles outlined by OWASP, including validation, error handling, and reduced attack surface.

Algorithms & Data Structures Enhancement

For the Algorithms and Data Structures outcome, I enhanced the goal management logic within the application by optimizing how user goals are processed, updated, and retrieved. The original implementation contained unnecessary iterations, repeated database queries, and minimal validation logic. These issues increased computational overhead and introduced opportunities for incorrect or inconsistent goal calculations.

The enhanced version focuses on algorithmic efficiency, improved data handling, and systematic validation. I consolidated redundant logic into single operations, reduced the number of database calls by structuring queries more effectively, and implemented clear conditional flows to ensure predictable and efficient behavior. These changes allow the controller to compute and maintain user financial goals with better performance and stability.

Data structures were also improved by ensuring that objects returned from the controller follow a consistent and predictable shape. Rather than dynamically constructing uneven objects, the refactored version enforces a stable data model, making downstream processing more reliable and reducing the need for defensive programming throughout the application.

Error conditions are now handled using explicit validation paths, preventing invalid goal parameters from propagating deeper into the system. This reduces the potential for logic errors, corrupt state, or broken financial projections. Additionally, separating validation, computation, and database interaction improves the maintainability and testability of the algorithmic logic.
